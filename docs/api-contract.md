# Действующий API для подключения frontend

Демонстрационный API: пользователи, разрешённые счета, переводы, история и
детские копилки с семейным пополнением и решением назначенного родителя.
Префикс всех маршрутов — `/api/v1`. Дата описания: 21.10.2026.
Схемы новых команд копилок, права и примеры: [копилки](piggy-banks.md).
Структуры остальных объектов сохранены в [JSON-контракте](json-exchange/api-contract.md).

## Запуск

В локальном `backend/.env`:

```dotenv
DEMO_MODE=true
DEMO_USER_ID=10
```

По умолчанию `DEMO_MODE=false`. Без демонстрационного режима health доступен,
а остальные маршруты ниже возвращают `403 DEMO_MODE_DISABLED`. При включении
режима запуск создаёт отсутствующие таблицы и демонстрационные записи.
Повторный запуск сохраняет остатки и историю.

PowerShell из корня `hacaton001`:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

На этом компьютере база API — `http://127.0.0.1:8000/api/v1`.
Для прямой проверки с другого устройства — `http://<BACKEND_LAN_IP>:8000/api/v1`,
с фактическим адресом backend-компьютера. Swagger — `/docs`, OpenAPI — `/openapi.json`.
Рабочий H5-интерфейс использует адрес своей страницы с `/api/v1`: Vite проксирует
`/api` на backend. Если backend на другом компьютере, задайте `API_PROXY_TARGET`
в `frontend/.env`. Только при прямых браузерных запросах на другой origin
задайте точный origin страницы в `CORS_ORIGINS`.

## Действующий пользователь и область доступа

Это явный демонстрационный выбор пользователя, **не настоящая аутентификация**.
Без дополнительного заголовка используется `DEMO_USER_ID=10`. Необязательный
`X-Demo-User-Id` выбирает существующую демонстрационную запись. Заголовок не
доказывает личность. Реальные персональные данные, реквизиты и деньги здесь
использовать нельзя.

Родитель читает собственные счета и переводит деньги между ними. Ребёнок читает
только явно подключённые к нему счета своего `parent_id`, включённые в ту же
семью; законный владелец счёта не меняется. История ребёнку доступна только при
`agree_parent.history`. Обычный `POST /transactions` ребёнку запрещён; для
пополнения копилки используется отдельная команда при `agree_parent.transaction`.
Администрирование семьи само по себе доступа к чужому счёту не даёт.

Переключатель «Родитель / Ребёнок / Участник семьи» выбирает ID `10 / 20 / 11`
через заголовок каждого запроса. Демо-семья — `1`, у ребёнка `20` назначен
`parent_id=10` и явно подключён счёт `101`. Другой родитель `11` использует свой
счёт `110`. Права копилок и безопасный ответ чужому ребёнку описаны
[отдельно](piggy-banks.md).

## Общий формат

- HTTP JSON UTF-8, `Content-Type: application/json`.
- Ресурс — объект; список — `{ "items": [...] }`. Обёртки `data` в JSON нет.
- ID — положительные целые числа. `cender` и `recipient` — ID счетов.
- Суммы BYN — целые копейки: `2500` означает 25,00 BYN. Максимум денежного
  значения — `9007199254740991`, безопасное целое JavaScript.
- Флаг — `true` / `false`, отсутствие значения — `null`, пустой список — `[]`.
- `Transaction.data` назначается сервером и возвращается в UTC ISO 8601 с `Z`.
- Связанные списки содержат ID. Существующие имена, включая `cender`, сохранены.
- Пароль и `Test.right_answer` не возвращаются в публичных данных.

## Маршруты

| Метод и путь после `/api/v1` | Ответ | Назначение |
| --- | --- | --- |
| `GET /health` | `200`, `{ "status": "ok" }` | Доступность приложения, без проверки БД |
| `GET /me` | `200`, `UserRead` | Демонстрационный пользователь |
| `GET /accounts` | `200`, `{ "items": [AccountRead] }` | Разрешённые счета |
| `GET /accounts/{id}` | `200`, `AccountRead` | Один разрешённый счёт |
| `GET /accounts/{id}/transactions` | `200`, `{ "items": [TransactionRead] }` | История при наличии права |
| `POST /transactions` | `201`, `TransactionRead` | Перевод родителя между своими счетами |
| `GET /pigs`, `POST /pigs`, `PATCH /pigs/{pig_id}` | `PigList` / `PigView` | Список, создание, имя копилки |
| `POST /pigs/{pig_id}/contributions` | `200`, `PigView` или квитанция | Пополнение разрешённым участником семьи |
| `POST /pigs/{pig_id}/break-requests`, `/break` | `RequestView` / `PigView` | Запрос ребёнка / разбитие назначенным родителем |
| `GET /pig-break-requests` и `POST .../{request_id}/approve`, `/reject` | `RequestList` / `RequestView` | Просмотр запросов и решение родителя |
| `GET /family/members` | `200`, `FamilyMemberList` | Публичные сведения своей семьи |

Полные тела команд, статусы и ответы новых маршрутов — в
[контракте копилок](piggy-banks.md#маршруты).

У истории query-параметры: `limit=50` по умолчанию, диапазон `1..100`;
`offset=0` по умолчанию, минимум `0`. Порядок — `data DESC`, затем `id DESC`.
Страница возвращает только `items`, без поля `total`.
В истории есть входящие и исходящие переводы; отдельные движения собственного
резерва копилки переводами не являются. Пустая история — `{ "items": [] }`.

### Пользователь

Начальный ответ `GET /me`:

```json
{
  "id": 10,
  "login": "demo_parent",
  "role": "parent",
  "accounts": [100, 101],
  "ECOfamily_id": 1,
  "newses_id": [],
  "test_id": [],
  "auto_transaction": []
}
```

`accounts` содержит ID разрешённых счетов: собственных у родителя и явно
подключённых у ребёнка. `ECOfamily_id` — ID семьи, на новой демо-БД это `1`.
`newses_id`, `test_id`, `auto_transaction` пока возвращаются как `[]`: учебный
прогресс и расписание не загружаются из БД. Названия и форма `UserRead` сохранены.

### Начальные счета и копилка

Данные ниже относятся к новой демонстрационной БД. Оба счёта активны и принадлежат
пользователю `10`.

| Счёт | `balance` | Резерв | `active_balance` | `limit` | `limit_period` |
| --- | --- | --- | --- | --- | --- |
| `100` | `20000` | `0` | `20000` | `15000` | `daily` |
| `101` | `10000` | `3000` | `7000` | `5000` | `daily` |

Другому родителю `11` принадлежит счёт `110`: `balance=15000`, резерва нет,
`active_balance=15000`, `limit=null`, `limit_period=null`. Ребёнку `20` явно
подключён счёт `101`; его `Account.user_id` по-прежнему равен `10`.

Копилка `500` принадлежит счёту `101` и привязана к ребёнку `20`, её цель —
`30000` копеек. GET копилок ребёнка показывает только его копилки. При чтении
счёта ребёнком `pigs` также содержит только ID его копилок; доступный остаток
учитывает весь резерв счёта. Если история ребёнку отключена,
`transactions_history=[]`, а маршрут истории отвечает `403 ACCESS_DENIED`.
`15000` — настройка демонстрации, а не законодательный предел.
`json-exchange/examples/entities.json` — отдельная фикстура: операция `900`
и учебные объекты из неё автоматически в рабочую БД не загружаются.

Пример начального ответа `GET /accounts/101`:

```json
{
  "id": 101,
  "user_id": 10,
  "balance": 10000,
  "pigs": [500],
  "active_balance": 7000,
  "active": true,
  "transactions_history": [],
  "limit": 5000,
  "limit_period": "daily"
}
```

`balance` включает копилки. Backend рассчитывает
`active_balance = balance − сумма current_balance копилок счёта`.
Все поля `AccountRead` описаны также в [структурах JSON](json-exchange/api-contract.md#account).

### Создание перевода

Тело `POST /transactions` содержит ровно три поля:

```json
{ "cender": 100, "recipient": 101, "amount": 2500 }
```

`amount` — строго положительное целое. Строки, дроби, `true`, ноль и лишние поля
не допускаются. Счета должны различаться. Клиент не передаёт `id`, `data`,
остатки, роль и ID действующего пользователя в этом теле.

Форма ответа `201`; ID и время в этом примере условные:

```json
{
  "id": 1,
  "cender": 100,
  "recipient": 101,
  "amount": 2500,
  "data": "2026-10-21T09:00:00Z"
}
```

На новой базе после одного такого перевода у счёта `100` будет остаток `17500`,
у `101` — общий остаток `12500` и доступный `9500`. Копилка сохраняет резерв `3000`.
Это ожидаемый пример, а не текущий остаток уже использовавшейся БД.

Сервис проверяет действующего родителя, владение обоими счетами, их активность,
доступный остаток источника, лимит и переполнение получателя. Списание,
зачисление и история сохраняются одной транзакцией БД. Для SQLite запись
начинается с `BEGIN IMMEDIATE`, чтобы конкурирующие запросы не проверяли один
устаревший остаток.

`active=false` блокирует операцию с любой стороны. `limit=null` вместе с
`limit_period=null` — отсутствие лимита; `limit=0` — запрет списаний. Лимит
считает исходящие переводы за календарный период UTC+03: день с 00:00,
неделю с понедельника, месяц с первого числа. Входящие переводы использованный
лимит не уменьшают. Поле `limit` — установленный предел, а не оставшаяся сумма.

После успеха frontend заново получает счета и историю. При сетевой ошибке
результат POST может быть неизвестен: автоматически повторять его нельзя.
Серверная идемпотентность повторных запросов пока не реализована.

## Ошибки

Демонстрационные маршруты используют безопасный единый формат:

```json
{
  "error": {
    "code": "INSUFFICIENT_FUNDS",
    "message": "Недостаточно доступных средств",
    "details": []
  }
}
```

| HTTP | `error.code` | Причина |
| --- | --- | --- |
| `401` | `DEMO_USER_NOT_FOUND` | Выбранного пользователя нет |
| `403` | `DEMO_MODE_DISABLED` | Режим демонстрации выключен |
| `403` | `ACCESS_DENIED` | Нет прав на счёт или операцию |
| `404` | `NOT_FOUND` | Счёт не найден |
| `409` | `ACCOUNT_FROZEN` | Один из счетов заморожен |
| `409` | `INSUFFICIENT_FUNDS` | Не хватает доступных средств с учётом копилок |
| `409` | `LIMIT_EXCEEDED` | Превышен лимит периода |
| `409` | `BALANCE_OVERFLOW` | Остаток получателя превысил бы безопасное целое |
| `422` | `VALIDATION_ERROR` | Неверный JSON, тип, поле или query-параметр |
| `503` | `DATABASE_BUSY` | SQLite не смогла получить блокировку за время ожидания |

В `details` ошибок валидации есть только `{ "field": "...", "code": "..." }`.
`input`, `ctx`, пароли и внутренние технические данные туда не включаются.
Для обработки используйте HTTP-статус и `error.code`, а не точный текст `message`.
Неизвестный маршрут возвращает `404 NOT_FOUND` в той же обёртке `error`.
Клиент также умеет разбирать прежний формат FastAPI `detail`; файл
`json-exchange/examples/error-fastapi.json` оставлен как проверка совместимости.

## Проверка через PowerShell

После запуска сервера во втором терминале:

```powershell
$apiBaseUrl = 'http://127.0.0.1:8000/api/v1'
Invoke-RestMethod "$apiBaseUrl/health"
Invoke-RestMethod "$apiBaseUrl/me"
Invoke-RestMethod "$apiBaseUrl/accounts"
Invoke-RestMethod "$apiBaseUrl/accounts/101"
Invoke-RestMethod "$apiBaseUrl/accounts/100/transactions?limit=50&offset=0"

$transferJson = @{ cender = 100; recipient = 101; amount = 2500 } | ConvertTo-Json -Compress
Invoke-RestMethod -Uri "$apiBaseUrl/transactions" -Method Post -ContentType 'application/json' -Body $transferJson
Invoke-RestMethod "$apiBaseUrl/accounts/100"
Invoke-RestMethod "$apiBaseUrl/accounts/101"
```

POST действительно меняет демонстрационную БД; повтор команды создаёт новый перевод.
Для явного выбора пользователя добавьте `-Headers @{ 'X-Demo-User-Id' = '10' }`.
Без этого заголовка используется настроенный `DEMO_USER_ID`.

## Получение на uni-app

В `frontend/src/api/api.js` уже есть `getHealth`, `getMe`, `getAccounts`,
`getAccount`, `getTransactions`, `createTransaction`, а также команды копилок.
`frontend/src/api/client.js` создаёт экземпляр и добавляет `X-Demo-User-Id` по
выбранному на экране профилю. Запросы H5 идут через same-origin прокси `/api`.
Для обычной работы экрана используйте готовый `api`, а не собирайте URL вручную.
Ниже — самостоятельный пример запроса истории родителя.

```javascript
const apiBaseUrl = `${window.location.origin}/api/v1`; // H5 через Vite-прокси
uni.request({
  url: `${apiBaseUrl}/accounts/100/transactions?limit=50&offset=0`,
  header: { 'X-Demo-User-Id': '10' },
  method: 'GET',
  dataType: 'json',
  success(res) {
    if (res.statusCode === 200) {
      const transactions = res.data.items; // массив обычных JS-объектов
      // Сохранить transactions в состоянии экрана / Pinia.
    } else {
      // Обработать res.data.error.code по HTTP-статусу.
    }
  }
});
```

Для перевода передавайте `data: { cender, recipient, amount }` и
`Content-Type: application/json`. Ручные `JSON.stringify` перед `uni.request` и
`JSON.parse` для `res.data` не нужны. В `success` всегда проверяйте HTTP-статус.
Если читаете текст локального JSON-файла, нужен один `JSON.parse(text)`.

`Test`, `News`, задания, питомец и автопереводы пока не имеют рабочих маршрутов.
Детская привязка, семейное участие и копилки реализованы; публичного маршрута
редактирования полного `ChaildProfile`, лимитов и заморозки пока нет.
Открытие настоящего банковского счёта и настоящая аутентификация
в демонстрационный API не входят.
