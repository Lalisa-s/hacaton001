# Веб-интерфейс семейного банка

Запускаемый uni-app (classic), Vue 3, JavaScript и Vite. Для текущего веб-демо
HBuilderX и отдельный uni-app builder не требуются.

## Запуск с обновлением при сохранении

Из корня `hacaton001` в PowerShell/PyCharm:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1
```

Терминал остаётся открыт; Ctrl+C останавливает процессы этого запуска.
Если backend уже работает, запускайте только интерфейс:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 frontend
```

- Интерфейс: http://localhost:5173
- Swagger: http://127.0.0.1:8000/docs
- Vue/CSS: сохранение файла обновляет страницу через Vite HMR.
- Python в `backend/app`: Uvicorn перезапускает API после сохранения.
- Данные: перечитываются после финансовых действий, по кнопке «Обновить» и каждые 10 секунд.
- Изменения `.env`, зависимостей и конфигурации запуска требуют перезапуска.

Можно запускать в двух терминалах. В первом, из `backend`:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload --reload-dir app
```

Во втором, из `frontend`, с установленным Node.js и npm:

```powershell
npm run dev:h5
```

На этом компьютере доступен встроенный Node без npm в PATH. Локальный npm
установлен в игнорируемой `work/tools/npm`; `dev.ps1` находит его автоматически.
На другом компьютере установите Node.js с npm, затем выполните `npm ci` в `frontend`.
Виртуальное окружение backend нужно создать отдельно по его README.

## Где писать код

- `src/pages/index/index.vue` — счета, модальное окно перевода, история и выбор демо-профиля.
- `src/components/PigSection.vue` — карточки копилок, пополнения и запросы родителю.
- `src/api/client.js` — адрес API и демо-заголовок `X-Demo-User-Id`.
- `src/api/api.js` — HTTP-запросы через `uni.request` и безопасные ошибки.
- `src/utils/money.js` — точное преобразование BYN ↔ целые копейки.
- `src/pages.json` — страницы uni-app; `src/manifest.json` — параметры приложения.
- `src/App.vue` — общие стили; `src/main.js` — создание Vue-приложения.
- `vite.config.js` — порт, HMR и прокси API.
- `tests/` — проверки контракта и денежных сумм.

Данные — обычные JS-объекты: `await api.getAccounts()` возвращает `{ items: [...] }`.
`uni.request` разбирает JSON автоматически. Vue хранит отображаемую копию в `ref`,
а сервер хранит и проверяет остатки. При переводе отправляется только
`{ cender, recipient, amount }`; `amount` — копейки. После успеха интерфейс заново
запрашивает счета и историю. POST не повторяется автоматически. При сетевой
ошибке сначала проверьте историю: сервер мог уже сохранить перевод.

## Телефон и второй компьютер

Откройте `http://<IPv4-компьютера-с-frontend>:5173` на устройстве в той же сети.
IPv4 найдите через `ipconfig`. Vite слушает `0.0.0.0`, порт фиксирован: 5173.
Если Windows запросит сетевой доступ, разрешите его для вашей частной сети.

Браузер отправляет `/api/v1/...` на адрес открытой страницы, а Vite проксирует
запрос на backend. Поэтому на телефоне не используется его собственный localhost.
Для backend на другом компьютере создайте `frontend/.env` по `.env.example` и
укажите `API_PROXY_TARGET=http://<IPv4-backend>:8000`, затем перезапустите Vite.
Backend должен слушать `0.0.0.0:8000`; настоящий IPv4 нельзя подменять примером.

`VITE_API_BASE_URL` оставьте пустым при работе через прокси. Если задаёте прямой
адрес API, добавьте точный origin страницы в backend `CORS_ORIGINS` и перезапустите
API. Wildcard с credentials не используется.

## Проверки и сборка

```powershell
npm test
npm run build:h5
```

Сборка появится в `dist/build/h5`. Dev-прокси в неё не включён: при размещении
нужен reverse proxy `/api` на FastAPI либо `VITE_API_BASE_URL` перед сборкой и
точный CORS origin. `dev.ps1` и dev-серверы предназначены для разработки/локального демо.

## Что работает

Счета с доступными остатками, отдельные карточки копилок, сведения о лимитах и
заморозке, перевод родителя в модальном окне и последние 50 операций.
Копилку можно создать, назвать, переименовать и пополнить. Ребёнок видит только
свои копилки и запрашивает разбитие; назначенный `parent_id` подтверждает или
отклоняет запрос либо разбивает копилку напрямую. Ожидающий запрос не освобождает
резерв. После подтверждения деньги доступны на прежнем счёте-владельце.

Переключатель «Родитель / Ребёнок / Участник семьи» выбирает демо-ID `10 / 20 / 11`
в заголовке каждого запроса; это не аутентификация. Детский доступ к счёту `101`
задан явно, владельцем остаётся родитель `10`. Ребёнку обычный
`POST /transactions` недоступен: он пополняет копилки отдельным запросом.
Другой член семьи пополняет со своего разрешённого счёта. При пополнении чужой
детской копилки ребёнком ответ содержит только `{ pig_id, amount }`.
Полные схемы и правила: [копилки](../docs/piggy-banks.md).

SQLite сохраняет суммы, имена, статусы копилок и запросы между запусками.
Новых зависимостей для копилок не требуется. Настоящего входа, банковской
интеграции, заданий, учебных модулей, питомца и автопереводов пока нет.

Не запускайте `npx degit ... .` поверх этой папки: приложение уже создано,
существующие конфиги и клиентские модули нужно редактировать здесь.

## Совместимость зависимостей

Версии uni-app взяты из официального Vue 3 preset. В нём зафиксирован старый
Vite 5.2.8; здесь dev-сервер обновлён до 6.4.4 через npm overrides.
С этой связкой проверены H5-сборка, загрузка API, HMR и перевод в браузере.
`package-lock.json` нужно хранить в Git и устанавливать через `npm ci`.
Vue оставлен 3.4.21 в соответствии со встроенным runtime uni-h5-vue.

`npm audit` после установки сообщает 37 проблем в дереве зависимостей uni-app
(7 low, 5 moderate, 25 high). Обновление Vite не устраняет унаследованные
проблемы всего toolchain. Не выполняйте `npm audit fix --force`: предлагаемые
версии DCloud относятся к другим линейкам и ломают эту сборку. Перед публичным
размещением потребуется отдельное совместимое обновление зависимостей.
Dev-сервер ограничен папкой frontend (`server.fs.strict=true`), CORS Vite
выключен; соседние файлы backend не входят в разрешённую папку.
