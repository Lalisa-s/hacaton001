# JSON на стороне uni-app

Здесь находится клиентский код обмена JSON для будущего uni-app frontend. Vue/uni-app приложение ещё не инициализировано: готовые модули можно подключить к проекту разработчика frontend.

- `src/api/api.js` — ES-модуль с `createApi`, `ApiError` и тремя вызовами API.
- `src/api/example-usage.js` — подключение и примеры работы с JS-объектами.
- `tests/test-api.mjs` — автономные проверки без npm и реальных сетевых запросов.
- `tests/test-fixtures.mjs` — проверка JSON из общей папки `../docs/json-exchange/examples/`.

Согласованный контракт и общие примеры находятся в `../docs/json-exchange/`.

В конфигурации frontend задайте полный адрес `http://<BACKEND_LAN_IP>:8000/api/v1`, подставив адрес компьютера, где работает backend. Передайте его в `configureApi(apiBaseUrl)`. IP не зашивается в библиотеку. Для браузера H5 origin вашего frontend должен быть явно разрешён настройкой CORS backend.

Сейчас работает только `GET /api/v1/health`. `GET /accounts/{id}` и `POST /transactions` показаны как проект будущего контракта. До их реализации сервер вернёт 404.

Перед отправкой формируется обычный JS-объект `{ cender, recipient, amount }`. Имена сохраняются по договорённости; стороны перевода — ID счетов. Сумма — положительное целое число копеек BYN. Балансы, роли и ID действующего пользователя с этой командой не отправляются. Backend отдельно проверяет владельца, права, остаток и лимит.

`uni.request` отправляет объект `data` с `Content-Type: application/json`. `dataType: 'json'` разбирает ответ, поэтому `response.data` уже объект или массив. Не вызывайте `JSON.stringify` перед запросом и `JSON.parse` после него. Результат — сам ресурс, например `{ "status": "ok" }`, без обёртки `data`.

Обёртка проверяет `statusCode`: callback `success` сам по себе не означает HTTP-успех. Только 2xx с объектом или массивом считается успехом этих методов. Строка/HTML/`null`/204 без тела приводят к `INVALID_RESPONSE`. Это проверка общего формата; проверка всех полей ресурса выполняется отдельными схемами по мере реализации контракта.

`ApiError` содержит `status`, `code`, безопасное локальное `message`, `details`. Поддерживаются будущие `{ error: { code, message, details } }` и текущие ошибки FastAPI `{ detail: [...] }` / `{ detail: "..." }`. Сообщения сервера не копируются в интерфейс: новые бизнес-коды добавляйте в `SAFE_MESSAGES`. Из validation details сохраняются только путь поля и код, без `input`, `ctx` и исходного текста ошибки. Не выводите в UI исходный ответ сервера и не логируйте пользовательские данные.

Автоматических повторов нет. Если POST завершился сетевой ошибкой, перевод мог уже состояться. После восстановления связи обновите историю и остатки; не повторяйте списание автоматически. Для безопасного повторения позже отдельно согласуем серверную идемпотентность.

Проверка из этой папки в PowerShell, если Node.js уже доступен:

```powershell
node .\tests\test-api.mjs
node .\tests\test-fixtures.mjs
```

Из корня репозитория команды начинаются с `node .\frontend\tests\...`.

`tests/test-fixtures.mjs` читает те же файлы из `../docs/json-exchange/examples/`, что и Python: текст файла
разбирается одним `JSON.parse`. В реальном uni-app ответ уже разбирает uni.request.

Официальная документация: [uni.request](https://uniapp.dcloud.net.cn/api/request/request.html).
